# Departures from OpenJPEG

neo-j2k follows OpenJPEG 2.5.4 on every valid complete stream, and the standard where OpenJPEG is wrong
on cut or invalid input (plan T5). Each departure is listed here with the test that holds it. There is no
compatibility switch. Departures are numbered DP-n and the oracle's known defects OD-n (`doc/oracle.md`),
apart from the owner's decisions D1-D15 and the fork audit's findings O1-O3.

| # | Case | OpenJPEG 2.5.4 | neo-j2k | Test |
|---|---|---|---|---|
| DP-1 | A packet cut inside a code-block's contribution, with mode switches (BYPASS, TERMALL) | the shipped DLL drops the code-block and every later one in the packet, earlier layers included | keeps every codeword segment completed before the cut (stage 1a's truncation fix, `c51e47ed`, which the oracle carries). ISO 15444-1 B.11 only allows dropping whole packets; keeping completed segments goes beyond it on purpose (plan audit B5) | `oracle_cuts.*` (the oracle has the semantics); `oracle_layers` (cuts at layer boundaries equal the whole file limited to those layers) |
| DP-2 | The DC shift at the 2^31 edge | decided differently on Windows and Linux (`tcd.c` clamp) | the same on every platform | stage 1c (crafted streams) |
| DP-3 | A tile whose tile-parts hold no data bytes (packed headers, every packet empty) | refused (`opj_j2k_decode_tile`) | candidate: decode it (valid per the standard); decided in stage 1c | `corpus/generated/edge_ppt_empty_tiles_97.j2k` (the reference records OpenJPEG's refusal) |
| DP-4 | A cut packed-header (PPM, PPT) stream with EPH | refused ("Expected EPH marker": oracle defect OD-1) | the layers that arrived complete decode | `oracle_layers` lists the case as a known oracle defect; from stage 1c neo-j2k must match the whole file limited to those layers |
| DP-5 | Marker precedence (plan W7): a COC, QCC or RGN that comes before the COD or QCD of the same header, in the main header or a tile's | the later COD or QCD overwrites every component, so the earlier COC or QCC is lost; a tile-part COC before the tile's COD likewise. The reduce factor is checked against every COD and COC as each is read | tile-part COC > tile-part COD > main COC > main COD (and QCC, QCD, RGN alike) whatever the order, as ISO 15444-1 A.6 has it; the reduce factor is checked against the components' parameters after precedence. A later marker of the same kind and component still replaces an earlier one, as in OpenJPEG | `header_unit` (`test_precedence`: a main COC before the COD, a tile COC before the tile COD; the oracle's facts show the lost COC) |
| DP-6 | A quantization with fewer step sizes than its component's sub-bands (plan W8) | accepted; the missing bands keep step sizes of 0, or those of an earlier QCD | refused (`NJ2K_E_HEADER`): checked for the main header's components when the header is read, and for each tile-component when its parameters are resolved (stage 1c) | `header_unit` (`test_quantization_counts`); three files of OpenJPEG's non-regression data (`dwt_interleave_h.gsr105.jp2`, `v4dwt_interleave_h.gsr105.j2k`, `4241ac03…_asan_heap-oob….jp2`) |
| DP-7 | Markers the decoder does not know | in the main header: skipped by scanning ahead for the next marker it knows, ignoring their length, so a SIZ can hide behind one; in a tile-part header: the tile-part fails. Part 2 markers (MCT, MCC, MCO, CBD) are read | a marker segment it does not know is skipped by its length, in both headers (ISO 15444-1 A.1); markers without a segment (0xFF30-0xFF3F) are skipped. SIZ must follow SOC. JPEG 2000 Part 2 markers (0xFF70-0xFF7F) are not supported (`NJ2K_E_UNSUPPORTED`, plan D7); EOC, SOD, SOP, EPH, PLT or PPT in the main header are refused | `header_unit` (`test_header_rules`); `issue476.jp2` of the non-regression data (an unknown marker with a length below 2: refused) |
| DP-8 | Values OpenJPEG lets through | an unknown progression order (an error message, then the decode goes on with no progression); a reserved quantization style (read as expounded); SIZ with no components | refused (`NJ2K_E_HEADER`) | `header_unit` (`test_header_rules`) |
| DP-9 | `nj2k_get_cstr_info`'s precinct sizes | `opj_get_cstr_info` copies `numresolutions` bytes of the per-resolution arrays, not elements, so only the first quarter of the resolutions get their sizes | every resolution's precinct size; the other fields as OpenJPEG gives them (`compno` 0, the step sizes of 1 or 3 x resolutions - 2 bands) | `header_facts` compares the bytes OpenJPEG fills |
| DP-10 | A stream whose read function returns 0 | called again for ever | the stream ends (`NJ2K_E_NEED_DATA` for a header) | `header_unit` (`test_api_rules`) |
