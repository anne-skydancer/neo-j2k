# Departures from OpenJPEG

neo-j2k follows OpenJPEG 2.5.4 on every valid complete stream, and the standard where OpenJPEG is wrong
on cut or invalid input (plan T5). Each departure is listed here with the test that holds it. There is no
compatibility switch. The header fuzz target compares every header read with the oracle's and stops on a
difference that the main header, or a JP2 file's boxes, do not explain by one of DP-5 to DP-8 and DP-11; the
decode fuzz target compares every decode the oracle's filter lets through and stops on a difference that
the main header, a tile-part header or the tile-parts' data do not explain by DP-3, DP-5 to DP-8, DP-12
or DP-14 (`fuzz/departures.h`). The reference tests leave out the corpus files of `tests/neoj2k-departures.txt`, and
the non-regression differential those of `tests/neoj2k-departures-nonregression.txt`, each tested on its
own.
Departures are numbered DP-n and the oracle's known defects OD-n (`doc/oracle.md`), apart from the
owner's decisions D1-D15 and the fork audit's findings O1-O3.

| # | Case | OpenJPEG 2.5.4 | neo-j2k | Test |
|---|---|---|---|---|
| DP-1 | A packet cut inside a code-block's contribution, with mode switches (BYPASS, TERMALL) | the shipped DLL drops the code-block and every later one in the packet, earlier layers included | keeps every codeword segment completed before the cut (stage 1a's truncation fix, `c51e47ed`, which the oracle carries). ISO 15444-1 B.11 only allows dropping whole packets; keeping completed segments goes beyond it on purpose (plan audit B5) | `oracle_cuts.*` (the oracle has the semantics); `oracle_layers` (cuts at layer boundaries equal the whole file limited to those layers) |
| DP-2 | The DC shift at its edges | a 9/7 sample of 2^31 becomes the minimum in the MSVC build (`opj_lrintf` gives INT_MIN) and the maximum in the Linux one; the 5/3 shift adds in 32 bits, undefined on overflow | a 9/7 sample of 2^31 or more gives the maximum, NaN and anything below -2^31 the minimum, on every platform, rounding to nearest with ties to even as `opj_lrintf`; the 5/3 shift adds in 64 bits and clamps | `decode_unit` (`test_dp2`: the scalar and AVX2 kernels and the tile-component function at the edges) |
| DP-3 | A tile whose tile-parts hold no data bytes (packed headers in PPM or PPT, every packet empty) | refused (`opj_j2k_decode_tile`: no data) | decided 2026-11-19 (owner, O-2): decoded, as the standard has it: every coefficient zero, so every sample the mid-value after the DC shift. A tile that never arrived, or whose bytes ended at the SOD of a cut `Psot = 0` tile-part, is still refused | `decode_unit` (`test_dp3`: the empty tiles are flat at the mid-value, and every request of the reference tables, on the whole file and on every prefix, equals the oracle's decode of the file with one byte padded after each empty tile-part's SOD); `corpus/generated/edge_ppt_empty_tiles_97.j2k` is left out of the reference tests (`tests/neoj2k-departures.txt`) |
| DP-4 | A cut packed-header (PPM, PPT) stream with EPH | closed: the oracle refused it (OD-1) until its pin moved to the published 1a (`03b3cddc`), which decodes the layers that arrived | the same as the oracle | `oracle_layers` and `neoj2k_layers` (cuts at layer boundaries equal the whole file limited to those layers); `oracle_cuts.packed_ppm_sop_eph_97` and `neoj2k_cuts.packed_ppm_sop_eph_97` |
| DP-5 | Marker precedence (plan W7): a COC, QCC or RGN that comes before the COD or QCD of the same header, in the main header or a tile's | the later COD or QCD overwrites every component, so the earlier COC or QCC is lost; a tile-part COC before the tile's COD likewise. The reduce factor is checked against every COD and COC as each is read | tile-part COC > tile-part COD > main COC > main COD (and QCC, QCD, RGN alike) whatever the order, as ISO 15444-1 A.6 has it; the reduce factor is checked against the components' parameters after precedence. A later marker of the same kind and component still replaces an earlier one, as in OpenJPEG | `header_unit` (`test_precedence`: a main COC before the COD, a tile COC before the tile COD; the oracle's facts show the lost COC) |
| DP-6 | A quantization with fewer step sizes than its component's sub-bands (plan W8) | accepted; the missing bands keep step sizes of 0, or those of an earlier QCD | refused (`NJ2K_E_HEADER`): checked for the main header's components when the header is read, and for each tile-component when its parameters are resolved (stage 1c) | `header_unit` (`test_quantization_counts`); three files of OpenJPEG's non-regression data (`dwt_interleave_h.gsr105.jp2`, `v4dwt_interleave_h.gsr105.j2k`, `4241ac03…_asan_heap-oob….jp2`) |
| DP-7 | Markers the decoder does not know | in the main header: skipped by scanning ahead for the next marker it knows, ignoring their length, so a SIZ can hide behind one; in a tile-part header: the tile-part fails. Part 2 markers (MCT, MCC, MCO, CBD) are read | a marker segment it does not know is skipped by its length, in both headers (ISO 15444-1 A.1); markers without a segment (0xFF30-0xFF3F) are skipped. SIZ must follow SOC. JPEG 2000 Part 2 markers (0xFF70-0xFF7F) are not supported (`NJ2K_E_UNSUPPORTED`, plan D7); EOC, SOD, SOP, EPH, PLT or PPT in the main header are refused | `header_unit` (`test_header_rules`: an unknown marker segment before SIZ, which the oracle reads); `issue476.jp2` of the non-regression data (an unknown marker with a length below 2: refused) |
| DP-8 | Values OpenJPEG lets through | an unknown progression order (an error message, then the decode goes on with no progression); a reserved quantization style (read as expounded) | refused (`NJ2K_E_HEADER`) | `header_unit` (`test_header_rules`, with the oracle reading both) |
| DP-9 | `nj2k_get_cstr_info`'s precinct sizes | `opj_get_cstr_info` copies `numresolutions` bytes of the per-resolution arrays, not elements, so only the first quarter of the resolutions get their sizes | every resolution's precinct size; the other fields as OpenJPEG gives them (`compno` 0, the step sizes of 1 or 3 x resolutions - 2 bands) | `header_facts` compares the bytes OpenJPEG fills |
| DP-10 | A stream whose read function returns 0 | called again for ever | the stream ends (`NJ2K_E_NEED_DATA` for a header) | `header_unit` (`test_api_rules`) |
| DP-11 | JP2 boxes after a box the reader skips (an unknown box, or an image box outside the JP2 header box) | the skip sets its state to `JP2_STATE_UNKNOWN`, which is 0x7FFFFFFF and so claims every box read: it then takes a JP2 header box with no file type box before it, reads image boxes that come before the JP2 header box as if they were in it (their image header or colour counts, the JP2 header box's own are ignored), and refuses a later file type box | the file type box must be the second box, and an image box outside the JP2 header box is ignored before it and read after it (as OpenJPEG reads one after it), as ISO 15444-1 I.4 and I.5.3 have the order | `header_unit` (`test_jp2`: an image box where the file type box belongs, read by the oracle; a colour box before the JP2 header box, which gives the oracle its colour space); `fuzz/regressions/header-jp2-image-box-before-ftyp.bin` |
| DP-12 | Progression order changes (POC) in both the main header and a tile's | the tile's changes are appended to the main header's; a change's layer end is taken as given | the tile's list replaces the main header's (ISO 15444-1 A.6.6); each change's layer end is bounded by the tile's layers | the decode fuzz target's departure check (`fuzz/departures.h`); none of the corpus or test data has both |
| DP-13 | `nj2k_end_decompress` on a JP2 file | reads the boxes after the codestream box, and can fail on them | reads nothing more: the decode is done, and the boxes after the codestream carry nothing the decoder uses; returns true | `decode_unit` (`test_dp13`: a box of length 4 after the codestream box, which the oracle's `opj_end_decompress` refuses) |
| DP-14 | HT code-blocks (JPEG 2000 Part 15, HTJ2K: the code-block style's bit 6 in a COD or COC) | decoded (OpenJPEG 2.5 has an HT block decoder) | not decoded yet: the header reads as OpenJPEG reads it, the decode is refused (`NJ2K_E_UNSUPPORTED`) until the HTJ2K module (owner decision D7) | the decode fuzz target's departure check; `nj2k_fuzz_decode_replay` over OpenJPEG's non-regression data (`htj2k/`) |
